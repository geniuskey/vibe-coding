번외 덱. 에이전트를 둘 이상 동시에 돌리기 시작한 분들을 위한 도구 소개입니다. herd는 영어로 '가축 무리' — 에이전트 여럿을 한 무리로 몰고 다니는 도구라고 기억하면 쉽습니다. 오른쪽 그림이 오늘의 요약: 왼쪽에 프로젝트(space)와 에이전트 상태 점, 오른쪽에 탭과 실제 터미널.
3분 요약 · TL;DR

결론부터 — 이 세 줄이면 됩니다

에이전트는 빨라졌는데 병목은 "누가 날 기다리나"를 찾는 나입니다. herdr가 그걸 대신 봐 줍니다.

  1. 1
    space → tab → pane, 두 단계로 정리합니다프로젝트는 space, 용도별 화면은 tab, 그 안의 진짜 터미널이 pane. 창 10개를 뒤질 일이 없습니다.
  2. 2
    에이전트 상태가 사이드바에 뜹니다 — 작업 중 · 답변 대기 · 완료화면을 읽어 상태를 알아채고 space까지 올려 보여 줍니다. 🙋 표시만 따라가면 됩니다.
  3. 3
    창을 닫아도 에이전트는 계속 돕니다백그라운드 서버가 터미널을 쥐고 있고, 화면은 붙었다 떼었다 하는 손님일 뿐입니다.

PROBLEM · 에이전트가 둘을 넘으면

에이전트는 빨라졌는데, 병목은 나입니다

🪟 창 찾기

터미널 창·탭이 열 개. 어느 게 어느 프로젝트인지 하나씩 눌러 봐야 압니다.

😴 노는 에이전트

"이 파일 고쳐도 될까요?" — 그 질문을 30분 뒤에 발견합니다. 그동안 에이전트는 멈춰 있었죠.

🔁 확인 왕복

끝났나? 창을 열어 보고, 아직이면 닫고, 또 열고. 확인하느라 내 시간이 다 갑니다.

필요한 건 더 빠른 에이전트가 아니라 — "지금 누가 날 기다리나"를 보여 주는 화면입니다.
청중에게 질문: 에이전트 두 개 이상 동시에 돌려 본 분? 그때 제일 귀찮았던 게 뭐였나요? 대부분 "어디 있는지 찾기"와 "끝났는지 확인하기"입니다. 에이전트의 속도가 아니라 사람의 주의력이 병목이 됩니다.
WHAT · herdr란

진짜 터미널은 그대로 두고, 구조를 얹는 도구

"Herdr is a terminal workspace manager. It keeps real terminal processes running and adds structure around them." — herdr 공식 문서 · Concepts

🦀 가볍게

Rust로 만든 실행 파일 하나. Electron 없음. 오픈소스(Apache-2.0).

⌨️🖱 둘 다

tmux식 ctrl+b 단축키도, 마우스 클릭도 됩니다. 패널 경계를 끌어 크기 조절까지.

🤖 에이전트를 알아봅니다

Claude Code · Codex · Copilot CLI · Cursor · OpenCode 등 — 상태를 읽어 냅니다.

$ brew install herdr                                 # macOS · mise · Nix도 됨
$ curl -fsSL https://herdr.dev/install.sh | sh       # Linux · macOS
$ herdr                                              # 실행 — 업데이트는 herdr update
tmux 같은 터미널 멀티플렉서인데, 처음부터 코딩 에이전트를 염두에 두고 만든 것이 차이입니다. Windows는 PowerShell 설치 스크립트(irm https://herdr.dev/install.ps1 | iex)가 따로 있습니다. 같은 이름의 데스크톱 앱(herdr-core 기반, macOS·Windows·Linux)과 모바일 앱도 나왔지만, 이 덱은 터미널판(Herdr TUI) 기준입니다. 데스크톱 앱과 TUI는 에이전트를 공유하지 않습니다.

STRUCTURE · 두 단계 분류

space → tab 두 단계로, 길을 잃지 않습니다

📁 space프로젝트 하나 — 저장소·작업·조사 하나에 하나씩
🗂 tab: agents용도별 화면
paneclaude · login
paneclaude · search
panecodex · etl
🗂 logs
🗂 server
🗂 review

space — 프로젝트를 나누는 서랍. 사이드바에 줄지어 섭니다.

tab — 한 프로젝트 안의 화면 배치. 에이전트용 · 로그용 · 서버용.

pane — 진짜 터미널 하나. 에이전트가 사는 곳.

서랍(space) 안에 칸막이(tab), 칸막이 안에 실제 물건(pane). 에이전트가 열 개여도 "어느 프로젝트의 어느 화면"으로 두 번만 고르면 됩니다. 용어 주의: 터미널판 공식 문서는 맨 위 단계를 workspace라고 부르고, 데스크톱 앱은 space라고 부릅니다. 같은 개념입니다. 탭 이름(agents · logs · server · review)은 공식 문서가 예로 드는 구성 그대로입니다.

STATUS · 핵심 기능

에이전트 상태 다섯 가지 — 누가 날 기다리나

상태뜻내가 할 일
working일하는 중그냥 둔다
blocked내 입력 · 승인 · 결정을 기다림지금 바로 간다 — 멈춰 있는 시간이 손해
done끝났는데 아직 내가 안 봄결과 확인 → 다음 일 주기
idle끝났고 확인도 함 — 대기 중새 일을 줄 수 있는 빈자리
unknown상태를 판단할 수 없음직접 들여다본다

⬆️ 위로 올라갑니다

pane → tab → space로 상태가 모입니다. 한 명이라도 blocked면 그 space가 통째로 빨갛게.

🎯 상태로 찾아가기

ctrl+b g Goto 창에서 blocked · done만 골라 바로 점프.

이게 herdr의 핵심. done은 에이전트가 보고하는 게 아니라 herdr가 "끝났는데 아직 안 봤다"를 기억해서 만든 상태입니다 — 그래서 놓치지 않습니다. blocked는 엄격하게 판정합니다: 정말 사람 입력이 필요할 때만 뜹니다.

"❯ 1. 예 / 2. 아니오"가 보이면 → blocked.

🪝 연동 설치 — 더 정확하게

$ herdr integration install claude

에이전트의 훅이 상태를 직접 보고합니다. codex · cursor 등도 같은 방식.

🔍 왜 그렇게 봤지?

herdr agent explain <pane> — 상태 판단의 근거를 보여 줍니다.

⚠️ pane 안에 tmux 금지

pane 속에서 tmux를 또 띄우면 에이전트가 가려져서 상태를 못 읽습니다.

지원 목록은 계속 늘어납니다: Claude Code, Codex, GitHub Copilot CLI, Cursor Agent CLI, OpenCode, Pi, Droid, Devin CLI 등은 화면 감지, Gemini CLI · Amp · Cline 등은 상태만. 목록에 없는 프로그램은 그냥 평범한 터미널로 동작합니다. 화면 감지로 못 맞히는 경우 idle로 떨어집니다 — 그럴 땐 integration을 설치하세요.

붙기 · 떼기

🪟 화면 (TUI)

보여 주기만 하는 손님

ctrl+b q화면만 떼기 (detach) — 에이전트는 계속
herdr다시 붙기 — 떠난 자리 그대로
herdr session list · attach · stop이름 붙인 세션을 여러 개 운영
herdr server stop전부 끄기 — 모든 pane이 종료됨
단, 재부팅하면 배치와 폴더만 돌아오고 프로그램은 새로 뜹니다 — 지원 에이전트는 저장된 세션으로 이어 가기 가능.
tmux를 써 본 분에게는 익숙한 구조. 퇴근할 때 터미널 창을 닫아도 서버가 살아 있으면 에이전트는 계속 돕니다. 노트북을 재부팅하면 프로세스는 살아남지 못합니다 — 화면 배치와 작업 폴더만 복원. 긴 작업은 재부팅 전에 마무리.

심화 · 스크립트로 부리기

에이전트도 herdr를 조종할 수 있습니다

$ herdr workspace create --cwd ~/project --label api   # space 만들기
$ herdr pane run w1:p2 "npm test"                      # 특정 pane에서 명령 실행
$ herdr agent wait w1:p1 --until done                  # 그 에이전트가 끝날 때까지 기다리기

🔗 "끝나면 다음"을 잇기

agent wait --until done 뒤에 다음 명령을 붙이면 — 사람 없이 바통 터치.

🔌 소켓 API

CLI는 로컬 소켓 위의 JSON API를 감싼 것. 상태 변화 이벤트를 구독해 알림·대시보드도 만듭니다.

herdr의 CLI는 모두 로컬 Unix 소켓(~/.config/herdr/herdr.sock)의 줄 단위 JSON API를 부릅니다. herdr api schema로 전체 스키마 확인. Claude Code에게 "herdr CLI로 pane 두 개 만들고 테스트를 돌려줘"라고 시키는 것도 가능 — 에이전트가 자기 작업 공간을 꾸리는 셈.

MY PICK · 발표자의 한마디

내가 herdr를 사용하는 이유

🗂 spaces → tabs, 두 단계로 정리

📁 vibe-coding        # space = 프로젝트
   ├ agents  logs  server   # tab = 용도별 화면
📁 side-project
   ├ agents  review

프로젝트는 space로, 그 안의 일은 tab으로 — 에이전트가 여럿이어도 어디서 뭘 하는지 한눈에.

🚦 agents 탭 — 누가 끝났고, 누가 날 기다리나

✅ feat-login     완료 — 결과 확인
🙋 feat-search    답변 대기 — 내 차례
⏳ refactor-db    작업 중

완료·답변 대기가 바로 보이니 멈춘 에이전트에 곧장 다음 일을 줍니다.

에이전트가 쉬지 않고 일하는 환경 — 내 할 일은 🙋 표시를 따라가는 것뿐입니다.
개인 경험담 슬라이드. spaces(프로젝트) → tabs(용도별 화면) 두 단계 분류라 에이전트 여러 개를 띄워도 길을 잃지 않는다. 특히 agents 탭에서 작업 완료 여부, 사용자 답변을 기다리는 상태가 바로 보인다 — 노는 에이전트가 없도록 계속 일을 줄 수 있어서 좋다.
START · 오늘 해 볼 것

세 단계로 첫 무리를 꾸려 보세요

① 설치 · 연동

brew install herdr
herdr integration install claude

② 프로젝트마다 space

ctrl+b shift+n 로 space를 만들고 agents 탭에 에이전트 2~3개.

③ 🙋만 따라가기

사이드바의 빨간 점이 뜨면 가서 답하고, 초록 점이면 결과 보고 다음 일.

여러 에이전트가 같은 파일을 고치면 충돌합니다 — 에이전트마다 작업 폴더를 나누는 법은 오케스트레이션 세미나의 git worktree 장에서.
처음엔 에이전트 두 개로 시작하세요. 셋 이상이면 에이전트보다 내가 결과를 검토하는 속도가 먼저 막힙니다. herdr는 화면을 정리해 줄 뿐, 같은 저장소에서 동시에 고치는 충돌은 막아 주지 않습니다 — worktree와 함께 쓰세요.
