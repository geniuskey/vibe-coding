# 바이브 코딩 실습 워크숍 — 강사용 런북

`workshop/index.html`을 **진행하는 사람**을 위한 운영 가이드다.
슬라이드에는 참가자용 정보가, 이 문서에는 강사·조교용 정보가 들어 있다.
(각 슬라이드의 발표자 노트(`S` 키)에도 슬라이드별 진행 멘트가 있다 — 이 문서는 그 위에 얹는 운영 계획이다.)

## 이 덱은 왜 이렇게 생겼나

초판은 8시간 동안 **실습 25개를 순서대로** 도는 구조였다. 실제로 진행해 보니
참가자들이 3~4개째에서 흥미를 잃고, 남은 시간을 자율 주제로 각자 만드는 쪽으로 넘어갔다.
원인은 난이도나 분량이 아니라 **형식의 단조로움**이었다:

| 초판의 문제 | 지금의 처방 |
| --- | --- |
| 25개 실습이 전부 "프롬프트 복사 → 붙여넣기 → 결과 확인" — 4개째부터 새로 배울 게 없다 | **실습 형식 5종**(스프린트·빈칸·구조·페어·보스전)을 돌려 쓴다. 같은 형식을 연속 두 번 하지 않는다 |
| 완성 프롬프트를 늘 제공 → 정작 **프롬프트 쓰는 연습은 하루 종일 0회** | **빈칸(BLANK)형** 도입. 프롬프트를 주지 않고 뼈대만 준다. 힌트는 접어 두고 5분 뒤에 연다 |
| 전부 첫 시도에 성공 → 긴장도 성취도 없다 | **보스전(DUEL)**: 정답이 심어진 웨이퍼 + 자동 채점기로 점수와 순위가 나온다 |
| 하루 종일 혼자 자기 노트북만 본다 | **페어(PAIR)** + 갤러리 워크 2회 + 프롬프트 공유 1회 |
| 자기 주제는 8시간째에야 등장 — 그래서 다들 거기로 건너뛴다 | **첫 20분에 자기 주제 확정.** 내 도구 v0 → v1 → v2 가 하루의 척추이고, 나머지 실습은 그 위에 얹는 기술 주입이다 |
| 8시간 고정 — 짧은 세션에서 쓸 수 없다 | **코스 3종**(90분 / 3시간 / 8시간). 실습마다 코스 칩이 붙어 있다 |

**빠진 실습은 삭제하지 않고 부록으로 남겼다.** 본편 뒤에 부록 실습 23개 + 심화 트랙이 그대로 있다.
참가자에게는 "오늘 못 한 것"이 아니라 "더 가져가는 것"으로 프레이밍할 것.

2개 붙였으면 갤러리 워크나 페어를 한 번 끼워 형식을 끊는다.

## 실습 형식별 운영 요령

형식마다 강사가 하는 일이 다르다. 이게 이 덱의 핵심이므로 형식을 뭉개지 말 것.

### ⚡ SPRINT — 프롬프트 제공, 속도전
- 완성 프롬프트를 주고 빠르게 결과를 낸다. **도파민 확보용**이지 학습의 중심이 아니다.
- 하루에 2~3회 이상 쓰지 않는다.

### ✍️ BLANK — 프롬프트 미제공 (가장 중요)
- **조교가 프롬프트를 대신 써 주면 이 실습은 실패다.** "지금 문장에서 빠진 게 뭘까요?"만 묻는다.
- 결과가 부실하게 나오는 것이 **정상이자 목적**이다. 고치는 루프를 자기 문장으로 처음 돌게 하는 게 목표.
- 시작 5분 뒤 강사가 전체에게 힌트 토글(`▸ 30초 넘게 막혔다면`)을 한 번 열어 준다.
- 끝나면 반드시 **프롬프트 공유**로 이어 붙인다. 자기 문장이 남에게 채택되는 경험이 만족도를 크게 올린다.

### 🚑 RESCUE — 고장난 것 살리기
- `data/buggy_yield.html`에 고장 3종이 심어져 있다: ① `ctx.fillRects` 오타 → 백지(콘솔 에러 복붙으로 해결)
  ② 색 조건 반전(묘사로 해결) ③ 제목 오기·y축 눈금 없음(국소 수정).
- **자르지 말 것.** "고장은 무섭지 않다"는 감각이 오늘의 진짜 수확 중 하나다.

### 👥 PAIR — 조종사 × 검사관
- 노트북 한 대. 조종사만 키보드를 잡고, 검사관은 **손을 대지 않고 질문만** 한다.
- **5분마다 실제로 종을 쳐야 교대가 일어난다.** 안 치면 아무도 안 바꾼다.
- 홀수 인원은 3인조(조종사 1 · 검사관 2). 인원이 적으면 강사가 검사관으로 들어간다.
- 목적은 SPC가 아니라 **검사관 역할 그 자체** — 검증 습관을 의지가 아니라 역할에 심는다.

### 🏆 DUEL — 보스전 (자동 채점)
- 참가자 화면: `data/boss/boss.html` (채점기) + `data/boss/boss_wafermap.csv`
- 채점은 브라우저 안에서만 이뤄지고 아무 데도 전송되지 않는다. 정답은 해시로 들어 있어 소스를 봐도 안 보인다.
- 진행: **15분 제작 + 5분 채점·시상.** 만점자가 나오면 프로젝터로 화면을 띄우고
  "어떤 프롬프트로 시작했나" 한 마디만 시킨다. 커피 쿠폰 하나면 방 분위기가 완전히 달라진다.
- 시간이 밀리면 **Q1~Q3만 필수**로 낮춘다(60점 통과).

## 시간이 밀렸을 때 — 스킵 우선순위

밀린 만큼 아래 순서대로 자른다 (위가 먼저):

1. **각 실습의 🚀 더 해보기 전부** — 원래 밸브다
2. **부록 실습** — 풀데이에서만 끼우는 것이므로 제일 먼저 뺀다
3. **패턴 카드 4장** · **KEY MESSAGE(도메인 지식 × AI)** — 읽고 넘기는 슬라이드
4. **LAB M-2 (v2 굳히기)** → 10분을 5분으로. "SKILL.md 만들어달라고 시키세요" 한 마디로 압축
5. **LAB P-1 (페어)** → 20분을 10분으로, 교대 2회
6. **보스전 통과 기준을 Q1~Q3(60점)으로** 낮추고 시상만 남긴다

**절대 자르지 않는 것**: 워크시트(주제 정하기) · **LAB M-0** · 고장난 앱 · **보스전** ·
갤러리 워크 1회 이상 · **쇼앤텔**.
자기 주제로 시작해서 남에게 보여주며 끝나는 이 축이 오늘의 전부다.

- 심화 트랙을 강사 라이브 데모로 (특히 GitHub Pages 배포 — 반응이 가장 좋다)

## 실습 판정 기준 (강사용)

슬라이드마다 "완료 조건"이 있지만, 진행 판단용 공통 기준은 다음과 같다.

| 실습 | 이 정도면 통과 (다음으로 넘어가도 됨) | 흔한 실패 → 처방 |
| --- | --- | --- |
| 워크시트 | 입력/출력 두 칸이 채워졌다 | 3분 넘게 고민 → 아이디어 카드에서 강제 선택 |
| M-0 (v0) | 화면에 뭐라도 뜬다 + 수정 요청 2회 | 완성하려 함 → "v0는 못생겨야 정상"으로 말린다 |
| R-1 (구조) | 백지 → 차트 복구 + 에러 복붙·묘사 둘 다 써봤다 | 콘솔을 안 봄 → "브라우저 콘솔 에러를 확인하고 고쳐줘" |
| B-1 (빈칸) | **자기 문장**으로 보내 봤고 한 번 고쳤다 | 조교가 대신 써 줌 → 그러면 이 실습은 무효 |
| D-1 (보스전) | 60점 이상 · 답을 손으로 세지 않았다 | CSV를 눈으로 훑음 → "도구가 세게 하세요"로 되돌린다 |
| P-1 (페어) | 위반 2건 검출 + 검사관이 숫자 하나를 원본과 대조 | 검사관이 키보드를 잡음 → 역할 재고지 |
| M-1 (v1) | 파일을 읽어서 뭔가를 보여준다 | 진도 격차 → 느린 사람은 **v0로 공유해도 통과** |
| M-2 (v2) | 파일 하나가 남았다 | 완성도 신경 씀 → "메모 한 장이면 충분" |

## 공통 트러블슈팅 대본

현장에서 반복되는 상황과 1차 대응. 설치 자체의 문제는 [0교시 트러블슈팅 TOP 5](../setup/)를 그대로 쓴다.

| 상황 | 대응 |
| --- | --- |
| 도구가 응답 없음/한도 초과 | 사용량 한도일 가능성 — 잠시 쉬거나 짝의 노트북으로. 고장이 아니라고 안심시키기 |
| 에러가 났는데 굳어 있음 | "에러는 복붙" 규칙 리마인드 — 첫 복붙 성공자를 공개 칭찬하면 이후 질문이 확 준다 |
| 결과가 산으로 감 | 복구 문장 사전 슬라이드로 — "아까 잘 되던 버전으로 되돌려줘" |
| 진도 격차가 벌어짐 | 빠른 사람에게 부록 실습 + 조교 역할(또는 옆 사람 검사관) 부여. 느린 사람은 완성보다 "루프 경험"에 집중 |
| 빈칸 실습에서 아무것도 못 씀 | 대신 써 주지 말고 **힌트 토글을 열어 준다**. 그래도 막히면 "무엇을 / 무엇으로" 두 조각만 채우게 한다 |
| 보스전 점수가 안 오름 | Q1(개수)로 되돌린다 — 도구가 파일을 제대로 읽는지부터 |
| 실데이터를 쓰고 싶어 함 | 오늘은 금지(보안 약속). "실데이터로 넘어가기 전 체크리스트" 슬라이드를 가리키기 |
| 한글 깨짐(CSV/엑셀) | "인코딩 문제인 것 같아, UTF-8로 다시 저장해서 읽어줘" 프롬프트 |

## 진행 팁

- **속도의 기준은 중앙값**: 최속·최지연 참가자가 아니라 방의 중간에 맞춘다. 양끝은 밸브(부록/조교 역할)로 흡수.
- **형식 전환을 말로 선언한다**: "자, 이번엔 프롬프트를 안 드립니다" / "이번엔 둘이서 합니다" — 전환을 소리 내어 알리는 것만으로 집중이 리셋된다.
- **몸을 일으키게 한다**: 갤러리 워크는 실제로 자리에서 일어나게 해야 효과가 있다. "설명 안 해도 된다"를 먼저 말해야 사람들이 화면을 연다.
- **화면 공유보다 URL**: 발표자 콘솔에서 발표를 시작하면 청중 화면이 자동 동기화된다. 뒤처진 사람은 "발표자 따라가기"를 끄고 자기 속도로 볼 수 있다.
- **질문은 Q&A 위젯으로**: 손들기보다 심리 장벽이 낮다. 쉬는 시간마다 질문 기록을 훑고 공통 질문만 전체 공유.
- **마무리 시간은 절대 희생하지 않는다**: 남에게 보여주는 순간이 자신감의 완성이다. 미완성도 공유 대상이라는 것을 반복해서 허락할 것.

## 자료 갱신 시 주의

- 시간표를 바꾸면 이 문서의 타임테이블과 슬라이드의 **`TODAY · 3시간 표준` 슬라이드 둘 다** 갱신할 것
- 실습을 추가/삭제하면 ① 코스 칩(`⚡90`/`🔷3h`/`⬛8h`) ② 스킵 우선순위 ③ 부록 개수(코스 카드·부록 커버) 를 재검토할 것
- **같은 형식이 연속으로 두 번 오지 않는지** 확인할 것 — 이 덱의 유일한 구조 규칙이다
- 보스전 데이터를 바꾸면 `data/boss/boss.html`의 정답 해시(FNV-1a)와 이 문서의 스포일러 표를 함께 갱신할 것
- 도구 설치·실행 명령의 최신성은 `setup/` 덱에서 관리한다 — 이 덱에서는 중복해 적지 않는다
