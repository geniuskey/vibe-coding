# 바이브 코딩 실습 워크숍 — 강사용 런북

`workshop/index.html`을 **진행하는 사람**을 위한 운영 가이드다.
슬라이드에는 참가자용 정보가, 이 문서에는 강사·조교용 정보가 들어 있다.
(각 슬라이드의 발표자 노트(`S` 키)에 장별 진행 멘트가 있다 — 이 문서는 그 위에 얹는 운영 계획이다.)

## 이 덱은 왜 이렇게 생겼나

초판은 8시간 동안 **실습 25개를 순서대로** 도는 구조였다. 실제로 진행해 보니
참가자들이 3~4개째에서 흥미를 잃고, 남은 시간을 자율 주제로 각자 만드는 쪽으로 넘어갔다.
원인은 난이도나 분량이 아니라 **형식의 단조로움**이었다:

| 초판의 문제 | 지금의 처방 |
| --- | --- |
| 25개 실습이 전부 "프롬프트 복사 → 붙여넣기 → 결과 확인" — 4개째부터 새로 배울 게 없다 | **실습 형식 5종**(스프린트·구조·빈칸·보스전·셀프 검증)을 돌려 쓴다. 손을 푸는 앞부분(워밍업·S-1·S-2)만 같은 형식이고, 그 뒤로는 형식이 연속되지 않는다 |
| 완성 프롬프트를 늘 제공 → 정작 **프롬프트 쓰는 연습은 하루 종일 0회** | 앞부분은 제공하고(복붙 OK), **뒤로 갈수록 안 준다**. R-1의 묘사 단계와 B-1은 뼈대만 주고 힌트는 접어 둔다 |
| 전부 첫 시도에 성공 → 긴장도 성취도 없다 | **보스전(BOSS)**: 정답이 심어진 웨이퍼 + 자동 채점기로 점수가 나온다. 점수는 각자 화면에만 보인다 |
| 첫 실습이 명함·점심 룰렛 같은 장난감 → 반응은 좋지만 다음 날 쓸 일이 없다 | 같은 난이도의 **업무 결과물**로 교체: S-1 단위 변환기(도구), S-2 회의 메모 → 회의록(문서). 워밍업도 오후 실습 용어 정리로 |
| 실습 25개가 다 별개 결과물 — 쌓이는 느낌이 없다 | 앞 실습은 전부 **마지막 실습의 준비운동**으로 배치. 마지막 30분에 자기 업무 도구 하나를 만들고 끝낸다 |
| 8시간 고정 — 짧은 세션에서 쓸 수 없다 | **코스 3종**(90분 / 3시간 / 8시간). 실습마다 코스 칩이 붙어 있다 |
| 마지막 실습(내 업무 도구)이 `○○` 빈칸 프롬프트 하나뿐 — 앞은 친절한데 마지막에 "알아서 하세요"가 된다 | **MY TOOL 사다리**: 도구 유형 4개(Ⓐ~Ⓓ) × 유형별 3단계 복붙 프롬프트(5·15·25분) + 연습 파일 정답 + 체크포인트·탈출 카드 |
| 부록 21개 — 장난감·본편 중복이 섞여 고르기 어렵다 | **레시피 11개**로 추림. 업무 파급력 순서로 번호를 매기고, 고르는 표(`#/ap-index`)를 앞에 둔다 |

### 설계 원칙: 전부 개인 작업

사내 실습이라는 전제에서, **짝을 짓거나 발표를 강요하는 장치는 넣지 않았다.**
다섯 형식 모두 혼자 한다. 진도 확인과 질문은 **Q&A 위젯의 익명 질문**으로 받는다 —
손을 들게 하거나 돌아가며 말하게 하는 것보다 심리 장벽이 훨씬 낮고, 강사도 어디서 막히는지 한눈에 본다.
마지막 공유도 **희망자만**이고, 아무도 손을 들지 않으면 강사가 돌아다니며 봐 둔 결과물 두세 개를
대신 소개하고 끝낸다.

## 실습 형식별 운영 요령

형식마다 강사가 하는 일이 다르다. 이게 이 덱의 핵심이므로 형식을 뭉개지 말 것.
**다섯 형식 모두 개인 작업이다.** 모든 실습 장은 같은 틀을 쓴다:
`배우는 것`(제목 아래) · `✅ 완료 기준 — 눈으로 확인` · `🚑 막히면`.

### ⚡ SPRINT — 프롬프트 제공, 복붙
- 완성 프롬프트를 주고 복사해 붙여넣으면 결과가 나온다. **자신감 확보용**이다.
- LAB 0(용어 정리)·S-1(단위 변환기)·S-2(회의록). 난이도를 일부러 바닥에 둔 구간이므로 **속도를 재촉하지 않는다.**
- 장난감 대신 **다음 날 쓸 수 있는 것**으로 골랐다. LAB 0의 용어표는 오후 보스전·SPC의 사전이 되고,
  S-1의 ②(아는 값으로 검산)는 하루 내내 이어지는 검산 습관의 첫 등장이다.
- 여기서 한 명이라도 못 따라오면 하루 종일 못 따라온다. 조교는 전원 화면에 결과가 뜬 것을 확인한다.

### 🚑 RESCUE — 고장 난 것 살리기
- `data/buggy_yield.html`에 고장 3종이 심어져 있다:
  ① `ctx.fillRects` 오타 → 콘솔에 `TypeError: ctx.fillRects is not a function`, 화면 백지(에러 복붙으로 해결)
  ② 막대 색 조건과 범례가 반대(90% 이상이 빨강) ③ 제목이 '웨이퍼 두께 모니터'·y축 눈금 없음.
- ①만 프롬프트를 주고, ②③은 **참가자가 화면을 보고 직접 묘사**한다("무엇이 지금 이런데, 이래야 해"). 힌트는 접혀 있다.
- ③ 되돌리기 연습: 일부러 "막대를 전부 회색으로" 시킨 뒤 "방금 바꾼 것만 되돌려줘". 되돌릴 수 있다는 걸 알면 겁이 준다.
- **자르지 말 것.** "고장은 무섭지 않다"는 감각이 오늘의 진짜 수확 중 하나다.

- **5분**: "STEP 1이 끝나 있어야 합니다." 계획이 4줄을 넘는 사람 → "절반으로 줄여줘"
- **15분**: "브라우저에서 열리나요?" 안 열리면 탈출 카드 🎯(범위 줄이기)·📋(에러 복붙)
- **20분**: "5분 남았습니다, 지금 되는 데까지가 오늘의 결과물입니다"를 크게
- **25분**: STEP 2까지 동작하면 통과. 바로 M-2로 넘어간다 (8시간 코스는 15분 더)

조교의 역할은 **완성하려는 사람을 말리는 것**과 **STEP 3에서 실데이터를 붙이려는 사람을 막는 것**이다.
'내 실제 형식'은 헤더와 형식만이고, 값은 끝까지 가짜다(오늘은 실데이터 금지). 형식이 떠오르지 않으면 연습 파일로 돌리게 한다 —
정답이 심어져 있어 검산이 된다. 미완성이 정상이라는 것을 반복해서 허락해야 마지막까지 분위기가 유지된다.

## 공통 트러블슈팅 대본

현장에서 반복되는 상황과 1차 대응. 설치 자체의 문제는 [0교시 — 설치와 기본 조작](../setup/)의 트러블슈팅을 그대로 쓴다.

## 진행 팁

- **속도의 기준은 중앙값**: 최속·최지연 참가자가 아니라 방의 중간에 맞춘다. 양끝은 밸브(레시피/🚀 더 해보기)로 흡수.
- **형식 전환을 말로 선언한다**: "자, 이번엔 프롬프트를 안 드립니다" / "이번엔 채점을 받습니다" —
  전환을 소리 내어 알리는 것만으로 집중이 리셋된다. 이게 지루함을 막는 가장 싼 도구다.
- **첫 실습에서 서두르지 않는다**: S-1은 전원이 결과를 볼 때까지 기다린다. 여기서 놓친 사람은 끝까지 못 따라온다.
- **발표를 강요하지 않는다**: 진도 확인은 익명 Q&A로, 마지막 공유는 희망자만.
  아무도 손을 안 들면 강사가 봐 둔 결과물 두세 개를 대신 소개하고 끝낸다.
- **화면 공유보다 URL**: 발표자 콘솔에서 발표를 시작하면 청중 화면이 자동 동기화된다.
  뒤처진 사람은 "발표자 따라가기"를 끄고 자기 속도로 볼 수 있다.
- **마지막 실습 시간은 절대 희생하지 않는다**: 오늘 유일하게 "내 것"을 만드는 시간이다.

## 자료 갱신 시 주의

- 시간표를 바꾸면 이 문서의 타임테이블과 슬라이드의 **`TODAY · 3시간 표준`·`TODAY · 8시간 풀데이` 장**을 함께 갱신할 것
- 장 사이 링크는 번호가 아니라 `<section id>`로 건다: `#/day-8h`, `#/m1-pick`, `#/m1-a`~`#/m1-d`, `#/m1-check`,
  `#/ap-index`, `#/ap-1`~`#/ap-11`, `#/adv-a1`, `#/adv-a4`, `#/mini-project`. 장을 넣고 빼도 링크는 안 깨지지만, id를 바꾸면 깨진다
- 연습 파일(`data/`)을 바꾸면 M-1 사다리 장의 「✅ 완료 기준 — 연습 파일이면」 정답, 데이터 팩 장의 발표자 노트, 이 문서의 표를 함께 갱신하고 **`data.zip`을 다시 묶을 것**:
  `cd workshop && rm data.zip && zip -X -r -q data.zip data -x 'data/boss/*' -x '*.DS_Store'`
- 실습을 추가/삭제하면 ① 코스 칩(`⚡90`/`🔷3h`/`⬛8h`) ② 스킵 우선순위 ③ 레시피 개수(코스 카드·레시피 표지·고르는 표) 를 재검토할 것
- 실습 장은 `배우는 것` · `✅ 완료 기준 — 눈으로 확인` · `🚑 막히면` 세 가지를 반드시 갖출 것
- **형식이 연속되지 않는지** 확인할 것 — 이 덱의 구조 규칙이다. 예외는 손을 푸는 앞부분(LAB 0·S-1·S-2)과 마지막 MY TOOL 묶음(M-1 ①·Ⓐ~Ⓓ·③ → M-2)뿐이고, 그 사실은 리듬 장에 명시돼 있다
- **개인 작업 원칙을 깨지 말 것** — 짝 실습·순회 발표·상호 평가를 추가하기 전에 대상 참가자에게 부담이 되지 않는지 먼저 확인한다
- 보스전 데이터를 바꾸면 `data/boss/boss.html`의 정답 해시(FNV-1a)와 이 문서의 스포일러 표를 함께 갱신할 것
- 보안 약속 3개 문구는 시리즈 공통이다(정본 `../security/`). 이 덱에서 바꾸지 말고, 워크숍 고유 수칙은 "이 워크숍에서 하나 더"로만 덧붙인다
- 도구 설치·실행 명령의 최신성은 `setup/` 덱에서 관리한다 — 이 덱에서는 중복해 적지 않는다
- 움직임은 타이틀 웨이퍼 맵 한 번 스캔(약 1초, 반복 없음)과 장 전환 fade뿐이다. `prefers-reduced-motion`이면 둘 다 끈다. 장식 애니메이션을 다시 넣지 말 것
