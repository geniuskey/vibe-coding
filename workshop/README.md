# 바이브 코딩 실습 워크숍 — 강사용 런북

`workshop/index.html`을 **진행하는 사람**을 위한 운영 가이드다.
슬라이드에는 참가자용 정보가, 이 문서에는 강사·조교용 정보가 들어 있다.
(각 슬라이드의 발표자 노트(`S` 키)에도 슬라이드별 진행 멘트가 있다 — 이 문서는 그 위에 얹는 운영 계획이다.)

## 이 덱은 왜 이렇게 생겼나

초판은 8시간 동안 **실습 25개를 순서대로** 도는 구조였다. 실제로 진행해 보니
참가자들이 3~4개째에서 흥미를 잃고, 남은 시간을 자율 주제로 각자 만드는 쪽으로 넘어갔다.
원인은 난이도나 분량이 아니라 **형식의 단조로움**이었다:

| 초판의 문제 | 지금의 처방 |
| --- | --- |
| 25개 실습이 전부 "프롬프트 복사 → 붙여넣기 → 결과 확인" — 4개째부터 새로 배울 게 없다 | **실습 형식 5종**(스프린트·구조·빈칸·보스전·셀프 검증)을 돌려 쓴다. 손을 푸는 앞부분(워밍업·명함·룰렛)만 같은 형식이고, 그 뒤로는 형식이 연속되지 않는다 |
| 완성 프롬프트를 늘 제공 → 정작 **프롬프트 쓰는 연습은 하루 종일 0회** | 앞부분은 계속 제공하고(복붙 OK), **뒤로 갈수록 안 준다**. 빈칸(BLANK)형에서는 뼈대만 주고 힌트는 접어 둔다 |
| 전부 첫 시도에 성공 → 긴장도 성취도 없다 | **보스전(BOSS)**: 정답이 심어진 웨이퍼 + 자동 채점기로 점수가 나온다. 점수는 각자 화면에만 보인다 |
| 실습 25개가 다 별개 결과물 — 쌓이는 느낌이 없다 | 앞 실습은 전부 **마지막 실습의 준비운동**으로 배치. 마지막 30분에 자기 업무 도구 하나를 만들고 끝낸다 |
| 8시간 고정 — 짧은 세션에서 쓸 수 없다 | **코스 3종**(90분 / 3시간 / 8시간). 실습마다 코스 칩이 붙어 있다 |

### 설계 원칙: 전부 개인 작업

사내 실습이라는 전제에서, **짝을 짓거나 발표를 강요하는 장치는 넣지 않았다.**
다섯 형식 모두 혼자 한다. 진도 확인과 질문은 **Q&A 위젯의 익명 질문**으로 받는다 —
손을 들게 하거나 돌아가며 말하게 하는 것보다 심리 장벽이 훨씬 낮고, 강사도 어디서 막히는지 한눈에 본다.
마지막 공유도 **희망자만**이고, 아무도 손을 들지 않으면 강사가 돌아다니며 봐 둔 결과물 두세 개를
대신 소개하고 끝낸다.

**빠진 실습은 삭제하지 않고 부록으로 남겼다.** 본편 뒤에 부록 실습 21개 + 심화 트랙이 그대로 있다.
참가자에게는 "오늘 못 한 것"이 아니라 "더 가져가는 것"으로 프레이밍할 것.

(<code>⚡90</code> / <code>🔷3h</code> / <code>⬛8h</code>)이 어느 실습이 포함되는지 알려준다.

| 코스 | 언제 쓰나 | 구성 |
| --- | --- | --- |
| ⚡ **90분 스프린트** | 팀 미팅 연장선, 점심 세미나, 맛보기 | 워밍업 → 명함(복붙) → 고장난 앱 → 보스전 → 내 업무 도구 |

**세 코스 모두 마지막 실습은 "내 업무 도구"다.** 길이가 달라도 끝나는 지점은 같다.

3시간 표준을 뼈대로 두고, 각 파트 뒤에 **부록 실습을 골라 끼운다**. 권장 삽입 지점:

**단, 부록을 연속 3개 이상 이어 붙이지 말 것** — 초판이 지루해진 이유가 정확히 그거였다.
2개 붙였으면 체크포인트나 다른 형식의 실습을 한 번 끼워 형식을 끊는다.

## 실습 형식별 운영 요령

형식마다 강사가 하는 일이 다르다. 이게 이 덱의 핵심이므로 형식을 뭉개지 말 것.
**다섯 형식 모두 개인 작업이다.**

### ⚡ SPRINT — 프롬프트 제공, 복붙
- 완성 프롬프트를 주고 복사해 붙여넣으면 결과가 나온다. **자신감 확보용**이다.
- 첫 두 실습(S-1·S-2)이 여기 해당한다. 난이도를 일부러 바닥에 둔 구간이므로 **속도를 재촉하지 않는다.**
- 여기서 한 명이라도 못 따라오면 하루 종일 못 따라온다. 조교는 전원 화면에 결과가 뜬 것을 확인한다.

### 🚑 RESCUE — 고장난 것 살리기
- `data/buggy_yield.html`에 고장 3종이 심어져 있다: ① `ctx.fillRects` 오타 → 백지(콘솔 에러 복붙으로 해결)
  ② 색 조건 반전(묘사로 해결) ③ 제목 오기·y축 눈금 없음(국소 수정).
- **자르지 말 것.** "고장은 무섭지 않다"는 감각이 오늘의 진짜 수확 중 하나다.

### ✍️ BLANK — 프롬프트 미제공 (가장 중요)
- **조교가 프롬프트를 대신 써 주면 이 실습은 실패다.** "지금 문장에서 빠진 게 뭘까요?"만 묻는다.
- 결과가 부실하게 나오는 것이 **정상이자 목적**이다. 고치는 루프를 자기 문장으로 처음 돌게 하는 게 목표.
- 시작 5분 뒤 강사가 전체에게 힌트 토글(`▸ 30초 넘게 막혔다면`)을 한 번 열어 준다.
- 끝나면 **패턴 카드 4장**으로 이어 붙인다. "내가 방금 쓴 문장에 이 중 몇 장이 있었나"를 스스로 채점하게 하는 슬라이드다.
- 발표시키지 않는다. 잘 나온 프롬프트가 있으면 **강사가 익명으로** 화면에 띄워 소개하는 정도로 충분하다.

### 🏆 BOSS — 보스전 (자동 채점)
- 참가자 화면: `data/boss/boss.html` (채점기) + `data/boss/boss_wafermap.csv`
- 채점은 브라우저 안에서만 이뤄지고 아무 데도 전송되지 않는다. **점수는 각자 화면에만 보이므로
  남과 비교당하는 부담이 없다.** 정답은 해시로 들어 있어 소스를 봐도 안 보인다.
- 진행: **15~20분 제작 + 5분 채점.** 만점자가 나오면 *원하는 경우에만* 화면을 띄우고
  "어떤 프롬프트로 시작했나" 한 마디를 부탁한다. 강요하지 않는다.
- 시간이 밀리면 **Q1~Q3만 필수**로 낮춘다(60점 통과).

### 🔍 SELF-CHECK — 혼자 검증하기
- 혼자 하면 AI 결과를 거의 의심하지 않게 된다. 그래서 **검증을 의지가 아니라 프롬프트로 만든다** —
  ②번 프롬프트("네가 만든 결과를 네가 검산해서 표로 보여줘")가 이 실습의 핵심이다.
- 오른쪽 「스스로에게 던지는 질문 3개」를 강사가 소리 내어 읽어 주고, 각자 자기 화면에서 확인하게 한다.
- 정답: 룰 1 위반 1건 + 룰 2(9점 연속) 1건. SPC 지식이 목적이 아니라 검산 습관이 목적이다.

### 🧰 MY TOOL — 마지막 실습, 주제는 각자
- **오늘 유일하게 주제가 사람마다 다른 실습이다.** 앞의 전부가 이걸 위한 준비였다고 명시해 준다.
- 주제를 못 정하는 사람이 반드시 나온다. 문진표 → 워크시트 → 아이디어 카드 순으로 30초씩 넘기며
  강제로 하나 집게 한다. **어느 걸 골라도 오늘 배울 것은 같다.**
- 완성하려는 사람을 말리는 게 조교의 주 임무. 미완성이 정상이라는 것을 반복해서 허락해야
  마지막까지 분위기가 유지된다.

## 시간이 밀렸을 때 — 스킵 우선순위

밀린 만큼 아래 순서대로 자른다 (위가 먼저):

1. **각 실습의 🚀 더 해보기 전부** — 원래 밸브다
2. **부록 실습** — 풀데이에서만 끼우는 것이므로 제일 먼저 뺀다
3. **패턴 카드 4장** · **KEY MESSAGE(도메인 지식 × AI)** — 읽고 넘기는 슬라이드
4. **LAB S-2 (룰렛)** — S-1로 이미 복붙 경험은 확보된다
5. **LAB M-2 (스킬로 굳히기)** → 강사 화면으로 1분 시연하고 "집에서 이 프롬프트 한 번 돌려보세요"로 압축
6. **LAB V-1 (셀프 검증)** → 20분을 10분으로. ②번 검산 프롬프트만 돌려 본다
7. **보스전 통과 기준을 Q1~Q3(60점)으로** 낮춘다

**절대 자르지 않는 것**: LAB S-1(첫 복붙 성공) · 고장난 앱 · **보스전** ·
주제 워크시트 · **LAB M-1(내 업무 도구)**.
쉬운 복붙으로 시작해서 내 업무 도구로 끝나는 이 축이 오늘의 전부다.

## 반대로 시간이 남으면

- 각 실습의 🚀 더 해보기로 심화
- 부록 실습을 삽입 (위 삽입 지점 표 참조) — **연속 3개 이상은 금지**
- 심화 트랙을 강사 라이브 데모로 (특히 GitHub Pages 배포 — 반응이 가장 좋다)
- LAB M-1을 25분 → 40분으로 늘린다. 이 실습은 시간이 길수록 결과물이 좋아진다

## 공통 트러블슈팅 대본

현장에서 반복되는 상황과 1차 대응. 설치 자체의 문제는 [0교시 트러블슈팅 TOP 5](../setup/)를 그대로 쓴다.

| 상황 | 대응 |
| --- | --- |
| 도구가 응답 없음/한도 초과 | 사용량 한도일 가능성 — 잠시 쉬거나 조교 노트북으로 이어서. 고장이 아니라고 안심시키기 |
| 에러가 났는데 굳어 있음 | "에러는 복붙" 규칙 리마인드 — 첫 복붙 성공자를 공개 칭찬하면 이후 질문이 확 준다 |
| 결과가 산으로 감 | 복구 문장 사전 슬라이드로 — "아까 잘 되던 버전으로 되돌려줘" |
| 질문이 안 나옴 | **Q&A 위젯의 익명 질문**을 가리킨다. 손 들기를 요구하지 않는다 |
| 진도 격차가 벌어짐 | 빠른 사람에게 🚀 더 해보기 또는 부록 실습. 느린 사람은 완성보다 "루프 경험"에 집중 |
| 빈칸 실습에서 아무것도 못 씀 | 대신 써 주지 말고 **힌트 토글을 열어 준다**. 그래도 막히면 "무엇을 / 무엇으로" 두 조각만 채우게 한다 |
| 보스전 점수가 안 오름 | Q1(개수)로 되돌린다 — 도구가 파일을 제대로 읽는지부터 |
| 마지막 실습 주제를 못 정함 | 아이디어 카드에서 **30초 안에** 하나 집게 한다. 어느 걸 골라도 배울 것은 같다 |
| 실데이터를 쓰고 싶어 함 | 오늘은 금지(보안 약속). "실데이터로 넘어가기 전 체크리스트" 슬라이드를 가리키기 |
| 한글 깨짐(CSV/엑셀) | "인코딩 문제인 것 같아, UTF-8로 다시 저장해서 읽어줘" 프롬프트 |

## 진행 팁

- **속도의 기준은 중앙값**: 최속·최지연 참가자가 아니라 방의 중간에 맞춘다. 양끝은 밸브(부록/🚀 더 해보기)로 흡수.
- **형식 전환을 말로 선언한다**: "자, 이번엔 프롬프트를 안 드립니다" / "이번엔 채점을 받습니다" —
  전환을 소리 내어 알리는 것만으로 집중이 리셋된다. 이게 지루함을 막는 가장 싼 도구다.
- **첫 실습에서 서두르지 않는다**: S-1은 전원이 결과를 볼 때까지 기다린다. 여기서 놓친 사람은 끝까지 못 따라온다.
- **발표를 강요하지 않는다**: 진도 확인은 익명 Q&A로, 마지막 공유는 희망자만.
  아무도 손을 안 들면 강사가 봐 둔 결과물 두세 개를 대신 소개하고 끝낸다.
- **화면 공유보다 URL**: 발표자 콘솔에서 발표를 시작하면 청중 화면이 자동 동기화된다.
  뒤처진 사람은 "발표자 따라가기"를 끄고 자기 속도로 볼 수 있다.
- **마지막 실습 시간은 절대 희생하지 않는다**: 오늘 유일하게 "내 것"을 만드는 시간이다.

## 자료 갱신 시 주의

- 시간표를 바꾸면 이 문서의 타임테이블과 슬라이드의 **`TODAY · 3시간 표준` 슬라이드 둘 다** 갱신할 것
- 실습을 추가/삭제하면 ① 코스 칩(`⚡90`/`🔷3h`/`⬛8h`) ② 스킵 우선순위 ③ 부록 개수(코스 카드·부록 커버) 를 재검토할 것
- **형식이 연속되지 않는지** 확인할 것 — 이 덱의 구조 규칙이다. 예외는 손을 푸는 앞부분(LAB 0·S-1·S-2)과 마지막 MY TOOL 두 장(M-1·M-2)뿐이고, 그 사실은 리듬 슬라이드에 명시돼 있다
- **개인 작업 원칙을 깨지 말 것** — 짝 실습·순회 발표·상호 평가를 추가하기 전에 대상 참가자에게 부담이 되지 않는지 먼저 확인한다
- 보스전 데이터를 바꾸면 `data/boss/boss.html`의 정답 해시(FNV-1a)와 이 문서의 스포일러 표를 함께 갱신할 것
- 도구 설치·실행 명령의 최신성은 `setup/` 덱에서 관리한다 — 이 덱에서는 중복해 적지 않는다
