# RTL / Verilog 도우미

RTL은 일반 텍스트라 파일 취급 제약이 없다. 이 스킬의 초점은 **분석·문서화·보일러플레이트**이며,
합성·타이밍 판단은 하지 않는다.

## 할 수 있는 일

### 1. 모듈 포트/파라미터 요약
- `module ... endmodule` 블록에서 파라미터, 포트(방향/폭/이름)를 추출해 마크다운 표로.
- ANSI/non-ANSI 포트 선언 둘 다 처리. `ifdef` 분기가 있으면 분기별로 명시.
- 산출 표는 사양서(spec-doc 스킬)에 그대로 붙일 수 있는 형식으로.

### 2. 셀프체킹 테스트벤치 뼈대 생성
- 포함: clk/rst_n 생성, DUT 인스턴스(포트 자동 연결), `$dumpfile/$dumpvars`,
  타임아웃 워치독, PASS/FAIL 카운터와 `$fatal`/`$finish`.
- 시나리오 본문은 `// TODO: scenario` 주석 슬롯으로 남긴다 — **시나리오 설계는 엔지니어의 일**.
- 파일명: `tb_<module>.v`. 기존 파일이 있으면 덮지 말고 `_v2`로.

### 3. 사내 코딩룰 체크
`references/lint_rules.md`의 룰로 정적 점검하고, 위반을 `파일:라인 — 룰 — 설명` 형식으로 보고.

## 검증

- `iverilog`가 설치되어 있으면 생성/수정한 파일을 컴파일해 문법을 확인한다:
  `iverilog -g2012 -o /dev/null tb_x.v x.v` — 실패하면 스스로 고치고 재시도.
- iverilog가 없으면 "문법 미검증" 상태임을 명시해서 전달한다.

## 하지 말 것

- 합성 가능성/타이밍/CDC 판단을 단정하지 않는다 — EDA 툴과 설계자 검토 영역.
- 기존 RTL의 동작 로직을 임의로 "개선"하지 않는다. 요청된 분석·생성까지만.
