🧠

개념 — Agent Skill이 뭔데?

프롬프트를 매번 다시 쓰는 대신, 사수의 매뉴얼처럼 한 번 써두고 계속 쓰는 것. SKILL.md 한 장이면 됩니다.

🏢

우리 회사 규칙 담기

DRM 걸린 엑셀은 xlwings·win32com으로, PPT/워드도 win32com으로 — 사내 제약까지 스킬에 새깁니다.

🛠️

실무 예제 7종 + 실습

측정 CSV 리포트, DRM 엑셀 요약, 주간보고 PPT, Word 사양서, GDS(KLayout), RTL/Verilog, TCAD 스윕.

코딩 지식 필요 없음 — 내 업무를 글로 설명할 수 있으면 그게 곧 스킬입니다.

전체 구조 안내: 개념(15분) → 사내 규칙(10분) → 예제 투어(30분) → 실습(나머지). "코드는 AI가 씁니다. 여러분은 일하는 법을 아는 사람입니다."
PROBLEM

어느 공정 엔지니어의 화요일 아침

  • 08:30 📥 설비 12대에서 내려온 측정 CSV를 하나로 모은다 40분
  • 09:10 🔒 DRM 걸린 수율 엑셀을 열어 어제 값 수기 복붙 30분
  • 09:40 📊 트렌드 차트 다시 그려서 그룹장 보고 메일 25분
  • 10:05 🖼️ 주간보고 PPT의 표·그래프 지난주 포맷에 맞춰 갱신 45분
  • 매주 같은 일, 같은 순서, 같은 포맷 — 판단은 5분, 손일은… 주 4시간+

이 일이 어려워서 오래 걸리는 게 아닙니다. 규칙이 내 머릿속에만 있어서 오래 걸립니다.

공감 유도: "본인 얘기 같은 분?" 시간은 예시일 뿐 — 각자 자기 반복 업무를 떠올리게 하기. 핵심 문장: 판단(엔지니어링)은 5분, 나머지는 규칙이 정해진 손일.

😮‍💨 설명이 일보다 길다

내 머릿속 규칙을 매번 처음부터. 조금만 빠뜨리면 결과가 엉뚱해집니다.

🎲 사람마다, 날마다 다르다

옆자리 동료의 프롬프트는 또 다르고, 지난달의 나는 뭐라고 썼는지 기억도 안 나고.

🚪 노하우가 퇴근하면 사라진다

담당자가 바뀌면 처음부터. 조직에 남는 게 없습니다.

프롬프트 자체의 한계가 아니라 "휘발성"의 문제. 다음 슬라이드에서 해법(스킬 = 저장된 프롬프트+규칙+도구) 제시.
CONCEPT

Agent Skill = 사수가 물려주는 업무 매뉴얼

🧑‍🏫 신입에게 일을 가르칠 때

매일 아침 옆에 앉아 처음부터 다시 설명하지 않습니다.

잘 정리된 매뉴얼 한 부를 주고, 모르면 그걸 펴 보게 하죠.

"이 업무는 언제 하는 거고, 순서는 이렇고, 이런 함정을 조심해."

🤖 AI에게 일을 가르칠 때

그 매뉴얼을 SKILL.md라는 텍스트 파일로 씁니다.

AI는 관련 업무 요청이 오면 스스로 그 매뉴얼을 꺼내 읽고 그대로 일합니다.

한 번 쓰면 — 나도, 동료도, 후임도, 내일의 나도 같은 품질.

스킬 = 발동 조건(언제) + 절차와 규칙(어떻게) + 도구(스크립트·참고자료)를 담은 재사용 폴더
비유 하나로 개념 전체를 전달. "prompt는 말로 시키기, skill은 매뉴얼 주기". Claude Code, Claude 앱 등 에이전트 제품들이 이 형식(Agent Skills)을 공통으로 지원한다는 점 언급.
ANATOMY

스킬의 실체는 그냥 폴더 하나입니다

📁 daily-meas-report/
├─ SKILL.md        ← 매뉴얼 본문 (필수)
├─ scripts/
│   └─ merge_csv.py ← 검증된 스크립트 (선택)
└─ references/
    └─ spec_table.md ← 스펙 표 등 참고자료 (선택)
--- SKILL.md 맨 위 (이름표) ---
name: daily-meas-report
description: 설비 측정 CSV들을 병합해
  일일 수율 리포트(HTML)를 만든다.
  "측정 리포트", "CSV 취합" 요청 시 사용.
--- 본문 (업무 매뉴얼) ---
1. data/*.csv 를 모두 읽는다 (skiprows=3)
2. LOT_ID 대문자 통일, THK 단위는 Å
3. 스펙 판정: references/spec_table.md 기준
4. 리포트는 새 파일 → 어떤 라이브러리든 OK

워드도 파워포인트도 아닌 일반 텍스트 — 메모장으로도 쓸 수 있고, 그래서 AI가 직접 써줄 수도 있습니다.

핵심: 겁먹을 필요 없다. 폴더 + 마크다운 텍스트가 전부. name/description = 이름표(발동 조건), 본문 = 절차, scripts/references = 부록.
HOW IT WORKS · 클릭해 보세요

AI는 매뉴얼을 필요할 때만 펼칩니다

📇 이름표 — daily-meas-report: 측정 CSV 병합·일일 리포트 생성…
📖 SKILL.md 본문 — ① CSV 읽기(skiprows=3) ② LOT_ID 정규화 ③ 스펙 판정 ④ HTML 리포트…
🧰 부록 — scripts/merge_csv.py 실행 · references/spec_table.md 참조

평소에는 이름표만 읽어 둡니다 — 매뉴얼 100권이 꽂혀 있어도 부담이 없습니다.

Progressive disclosure를 "책장의 매뉴얼" 비유로: 평소엔 책등(이름표)만, 일 생기면 그 권만 펼친다. 그래서 스킬을 수십 개 만들어도 AI가 느려지거나 헷갈리지 않는다 → 팀 스킬 라이브러리가 가능한 이유. 스텝 버튼 클릭하며 시연.
BEFORE / AFTER · 탭을 눌러 보세요

같은 요청, 스킬 없이 vs 스킬로

💬 나 → AI (매번, 전 항목 기억해서)
"D:\meas 폴더 CSV 합쳐줘. 헤더 3줄 스킵하고, LOT_ID 대문자로,
THK는 Å 단위, CVD 스펙 450±30 / Etch 1200±80으로 판정하고,
차트는 파란색-주황 순서로, 파일명은 daily_YYMMDD.html로…"
설명 비용
~1,100자 × 매번

빠뜨린 규칙 하나 = 다시 설명 + 재실행. 품질이 그날의 기억력에 달려 있습니다.

💬 나 → AI
"어제 측정 리포트 뽑아줘"
설명 비용
한 줄. 규칙은 스킬이 기억

AI가 daily-meas-report 스킬을 찾아 펼치고, 그 안의 규칙·스크립트대로 실행합니다. 누가 시켜도 같은 품질.

탭 전환 시연. 강조: 스킬이 프롬프트를 대체하는 게 아니라 "반복되는 설명"을 흡수하는 것. 일회성 요청은 여전히 그냥 프롬프트로.

💬 이렇게 시작하면 됩니다 (복사해서 그대로)
skill-creator 스킬을 사용해서 새 스킬을 만들어줘.
업무: 매일 아침 설비별 측정 CSV(D:\meas\*.csv)를 병합해 일일 리포트를 만든다.
규칙: 헤더 3줄 스킵, LOT_ID 대문자, THK는 Å, 스펙 판정은 CVD 450±30.
주의: 회사 엑셀 파일은 DRM 때문에 반드시 xlwings로만 열 것.

여러분이 준비할 것은 코드가 아니라 업무 설명입니다 — 신입에게 말로 가르친다고 생각하고 쓰면 끝.

skill-creator: 스킬 작성 모범 규칙(이름표 쓰는 법, 본문 구조, scripts 분리)을 아는 메타 스킬. Claude가 인터뷰하며 빠진 규칙을 되물어 줌 → 비개발자에게 최적. 마지막 줄 강조: DRM 같은 사내 제약도 "말로" 넣으면 스킬에 새겨진다.
QUALITY CHECKLIST

좋은 매뉴얼의 조건 = 좋은 스킬의 조건

  • ① 이름표(description)가 발동 조건

    "측정 리포트", "CSV 취합" 같은 내가 실제로 쓰는 말을 넣어야 AI가 알아서 꺼내 씁니다.

  • ② 규칙은 애매함 없이

    "적당히 정리" ❌ → "LOT_ID는 대문자, 소수점 1자리" ⭕. 신입이 읽고 바로 할 수 있는 수준으로.

  • ③ 검증 방법을 명시

    "행 수가 원본 합계와 같은지 확인", "스펙 밖 랏 수를 로그로 출력" — AI가 스스로 검산하게.

  • ④ 함정·제약을 기록

    "이 엑셀은 DRM이라 xlwings 필수", "금요일 파일은 컬럼이 하나 더 많음" — 고생한 기억이 조직의 자산이 되는 순간.

완벽하게 시작할 필요 없습니다 — 스킬은 쓰면서 다듬는 살아있는 문서입니다.
④가 오늘 세미나 후반부와 직결: DRM/KLayout 같은 사내·도구 제약이 바로 "함정 기록"의 대표 사례.

사내 문서는 DRM으로 암호화되어 있어, 파일을 직접 파싱하는 라이브러리(pandas·openpyxl)에게는 암호문 덩어리로 보입니다.

Excel·PowerPoint·Word 앱 자체는 DRM을 해독할 권한이 있으므로, xlwings/win32com으로 앱을 조종해서 읽고 쓰면 됩니다. (우회가 아니라 정식 경로!)

애니메이션: 위 레인은 파일이 자물쇠에 막혀 소멸, 아래 레인은 Excel 앱을 통해 통과. "AI가 이걸 모르면 pandas부터 시도하고 실패한다 → 그래서 이 규칙을 스킬에 박아야 한다"로 다음 슬라이드 연결.

win32com = pywin32 패키지의 COM 자동화(win32api 계열). xlwings는 그 위의 친절한 포장. "새로 생성은 자유" — DRM은 저장 후 정책에 따라 적용되므로 생성 자체는 표준 라이브러리로 가능.

# office-drm/SKILL.md (발췌)
name: office-drm
description: 사내 엑셀/PPT/워드 파일을 읽거나
  수정할 때의 필수 규칙. Office 문서 작업 전 반드시 참조.

## 철칙
- 기존 .xlsx: xlwings 또는 win32com만 사용.
  pandas.read_excel / openpyxl로 직접 열기 금지 (DRM 파손)
- 기존 .pptx/.docx: win32com만 사용
- 새 파일 생성: 라이브러리 자유
- 작업 후 반드시 앱 종료(quit)로 잠금 해제

💡 무엇이 좋아지나

이제 누가 어떤 요청을 하든 — "수율 엑셀 정리해줘" — AI가 알아서 xlwings 경로를 탑니다. 실패-재시도 없이, 팀원 모두 동일하게.

각 예제 = 시나리오 1장 + 데모 1장 페이스. 시간 부족하면 4번(Word)과 7번 데모는 건너뛸 수 있게 설계.
예제 1

표준 측정 CSV → 일일 리포트

새 파일 생성 = 라이브러리 자유

설비들이 뱉는 표준 포맷 CSV(랏, 웨이퍼, 두께, 균일도…)를 병합해 스펙 판정 + 트렌드 차트가 담긴 HTML 리포트를 만듭니다.

# csv-report/SKILL.md (발췌)
description: 표준 측정 CSV 병합→일일 리포트.
  "측정 리포트", "CSV 취합", "수율 정리" 시 사용

## 절차
1. 대상 폴더의 *.csv 로드 — 헤더 3줄 스킵
2. LOT_ID 대문자, 날짜는 YYYY-MM-DD 통일
3. 스펙 판정: references/spec_table.md
4. 산출물: report_YYMMDD.html (새 파일 → 자유)
## 검증
- 병합 행수 = 파일별 행수 합 (다르면 중단·보고)

👀 여기서 볼 것

규칙("헤더 3줄", "대문자")이 코드가 아니라 한국어 문장으로 들어있다는 점.

✅ 검증 절차 내장

행수 검산이 스킬에 있으므로 AI가 스스로 이상을 감지하고 멈춥니다 — "조용히 틀리는" 자동화 방지.

표준화된 CSV라는 전제가 중요: 포맷이 표준이면 스킬은 극도로 안정적. 포맷이 들쭉날쭉하면? → "포맷 정규화"가 스킬의 1단계가 되면 된다.

예제 2

DRM 엑셀 수율 대장 요약

기존 파일 = xlwings 필수
# ❌ 스킬이 없을 때 AI가 저지르는 실수
import pandas as pd
df = pd.read_excel("수율대장.xlsx")
→ XLRDError / 깨진 바이트: DRM 암호문을
  직접 읽으려다 실패
# ✅ drm-excel 스킬이 시키는 방법
import xlwings as xw
app = xw.App(visible=False)
wb = app.books.open(r"수율대장.xlsx")  # Excel이 DRM 해독
data = wb.sheets["주간"].range("A1").expand().value
...
wb.save(); wb.close(); app.quit()  # 잠금 해제 필수
# drm-excel/SKILL.md 핵심 규칙 (발췌)
- 기존 사내 xlsx는 반드시 xlwings(또는 win32com)로 Excel 앱을 경유해 연다
- visible=False로 조용히, 단 끝나면 반드시 quit() — 안 하면 파일이 잠긴 채 남는다
- 대량 셀은 range().expand().value로 한 번에 (셀 하나씩 루프 금지 — 100배 느림)
- 저장 전 원본 백업 사본 생성, 수정한 셀 주소를 로그로 남긴다
왼쪽 실패 사례를 먼저 — 스킬 없는 AI는 누구나 pandas부터 시도한다. quit() 규칙: 현업에서 진짜 자주 나는 사고(잠긴 엑셀). 이런 게 "함정 기록"의 가치. win32com 직접 쓰는 버전도 skills 폴더에 주석으로 포함.

description: 주간보고 PPT 갱신. "주간보고",

2. win32com으로 PowerPoint 열기:

3. 슬라이드 2 제목의 날짜 갱신 (W29 → W30)
4. 슬라이드 3 표: report_*.html의 주간 집계로 교체

🧷 템플릿 = 지난주 파일

디자인을 코드로 다시 만들지 않습니다. 복사 후 값만 교체 — 팀 포맷이 100% 보존됩니다.

🪆 함정: 차트 속의 엑셀

PPT 차트 안에는 미니 엑셀이 숨어 있습니다. 이것도 파일 직접 파싱이 아닌 COM 경유로 — 이런 디테일이 스킬에 적혀 있어야 하는 이유.

"복사 후 교체" 패턴은 Word에도 동일 적용. python-pptx는 새 PPT를 만들 때만(생성은 자유), 기존 사내 PPT는 win32com.

📌 문서 규정과 자동화의 공존

개정 이력, 강조 표시, 승인 후 저장 — 팀의 문서 관리 규정 자체가 스킬 절차에 들어갑니다.

🤝 사람이 마지막 관문

"보고 → 승인 → 저장" 순서를 스킬에 명시하면, AI는 절대 승인 없이 저장하지 않습니다.

시간 조절용 슬라이드(데모 생략 가능). 핵심 전달: 절차 안에 "사람 승인" 게이트를 넣을 수 있다.
예제 5

GDS 레이아웃 검사

.gds = KLayout

레이아웃 .gds는 엑셀로도 메모장으로도 못 엽니다. 표준 오픈소스 KLayout의 파이썬 모듈(pya)이 정답.

# gds-inspect/SKILL.md (발췌)
description: GDS/OASIS 레이아웃 검사·통계.
  "GDS 열어줘", "레이어 면적", "밀도 체크" 시 사용

## 절차 (pip install klayout)
import klayout.db as db
ly = db.Layout(); ly.read("chip.gds")
- 셀 트리·인스턴스 수 요약 (top_cell부터)
- 레이어별 도형 수·면적 → 표로
- 밀도 체크: Region으로 면적/윈도우 계산
- 좌표 단위는 dbu! ly.dbu 곱해 µm 변환 필수
## 금지
- GDS 바이너리를 직접 파싱하는 코드 작성 금지

🎯 현업 활용처

테스트 패턴 면적 집계, 레이어 커버리지 리포트, 룰 위반 후보 스크리닝, 리비전 간 레이아웃 diff.

⚠️ 함정: dbu 단위

KLayout 좌표는 정수 dbu(보통 1nm). µm로 착각하면 천 배 틀립니다 — 이런 함정이야말로 스킬에 적을 1순위.

본격 DRC/LVS는 전용 툴 영역 — 스킬의 역할은 "가벼운 검사·통계·리포트 자동화". 다음 장에서 GDS가 어떻게 생겼는지 직접 만져보기.

# tcad-sweep/SKILL.md (발췌)
description: TCAD 입력덱 파라미터 스윕 생성과 결과(I-V) 추출·요약. "스플릿 돌려줘", "Vth 뽑아줘" 시 사용
## 규칙
- 입력덱은 텍스트 — 템플릿 복사 후 자리표시자만 치환 (물리 모델 라인은 절대 수정 금지)
- 스윕 조건은 sweep_plan.csv 한 곳에서만 관리 · 결과 파일명 = 조건 조합 (tox12_nd5e17.csv)
- Vth 추출법은 정전류법(Id=100nA×W/L)으로 통일 — 사람마다 다르면 비교 불가
- 시뮬레이터 라이선스/큐 제출 명령은 references/cluster.md 참조

시뮬레이터 자체(Sentaurus 등)는 그대로 — 스킬이 자동화하는 건 그 앞뒤의 덱 생성과 결과 정리입니다.

"Vth 추출법 통일" — 분석 방법의 표준화가 스킬의 숨은 가치. 조직 데이터의 비교 가능성. 다음 장: 그 결과물이 어떤 그림이 되는지.

코드 리뷰는 어렵지만 매뉴얼 리뷰는 누구나 할 수 있습니다 — "이 스펙 바뀌었어요", "이 함정도 추가해요". 비개발자도 기여자가 됩니다.

👁️ 검증은 엔지니어의 몫

🔐 데이터는 회사 담장 안에서

공정 데이터·레이아웃·RTL은 사내 승인된 AI 환경에서만. 외부 서비스에 붙여넣기 금지 — 스킬 본문에도 이 규칙을 명시하세요.

🚫 DRM은 우회 대상이 아님

xlwings/win32com은 권한 있는 앱을 통한 정식 접근입니다. DRM 해제·변환 시도는 스킬에 '금지'로 못 박아 두세요.

좋은 스킬은 능력만이 아니라 하지 말아야 할 것까지 물려줍니다 — 그게 진짜 사수죠.
