② CLAUDE.md

CLAUDE.md는 세션마다 자동으로 읽히는 안내문입니다

작업 폴더 맨 위에 CLAUDE.md를 두면 Claude Code가 세션을 시작할 때 먼저 읽습니다. 신입에게 주는 첫날 안내문을 AI에게 써 두는 셈입니다.

  • 📁 폴더의 CLAUDE.md — 이 업무 규칙, 팀과 공유
  • 🏠 ~/.claude/CLAUDE.md — 내 개인 습관
  • ⚡ /init 초안 생성 · /memory 바로 고치기

다른 에이전트 도구는 AGENTS.md 같은 이름으로 같은 역할을 합니다.

📁 yield-analysis/   ← 수율 분석 작업 폴더
├─ CLAUDE.md        ← 매 세션 자동으로 읽힘
├─ data/            ← 측정 CSV (읽기 전용)
├─ reports/         ← 결과물은 새 파일로
└─ .claude/skills/  ← 절차는 스킬로 (뒤에서)
위치와 자동 로드만 기억하면 됩니다. /init은 폴더를 훑어 초안을 써 주고, /memory는 메모 파일을 바로 엽니다. 개인용(~/.claude/CLAUDE.md)과 폴더용을 구분합니다. 팀이 같이 지킬 규칙은 폴더용에 둡니다. CLAUDE.md는 매번 읽히는 만큼 컨텍스트 자리를 차지합니다 — 원리는 컨텍스트 덱(../context/)에서.
② CLAUDE.md · 예문

좋은 CLAUDE.md는 숫자와 금지로 씁니다

# CLAUDE.md — CVD/Etch 일일 수율 분석

## 이 폴더는
- 입력: data/*.csv (설비 표준 포맷, 맨 위 3줄은 헤더)
- 결과: reports/ 아래 새 파일. data/는 읽기 전용

## 규칙
- 두께 THK_A는 Å 그대로. 단위 변환 금지
- LOT_ID는 대문자로 통일해서 집계
- 사내 .xlsx·.pptx는 office-drm 스킬을 따른다

## 완료 기준
- 보고에 "병합 행수 = 파일별 행수 합" 검산 결과
- 확인하지 않은 것은 "미확인"이라고 쓴다

## 하지 말 것
- 실데이터를 사외 서비스에 붙여넣지 않는다

🔍 판정할 수 있게

"깔끔하게" 대신 "Å 그대로", "대문자". 지켰는지 예·아니오로 답할 수 있어야 합니다.

🚫 금지가 힘이 셉니다

AI가 친절하게 바꾸려 드는 곳(단위, 원본 파일)엔 "~금지"로 못 박습니다.

규칙 목록만. 길어지면 매 세션 자리를 차지합니다 — 긴 절차는 스킬로 뺍니다.

🔁 두 번 지적하면 한 줄 추가

"방금 지적한 것 CLAUDE.md에 추가해줘" — 교훈이 파일에 쌓입니다.

그대로 가져다 쓸 수 있는 예문입니다. 모든 줄이 "지켰나?"에 예·아니오로 답할 수 있게 적혀 있다는 점을 짚습니다. 완료 기준을 적어 두면 "다 됐습니다" 대신 검산 결과를 보고받습니다. 오른쪽 네 요령 중 운영의 핵심은 마지막 — 같은 지적을 두 번 했다면 대화가 아니라 파일에 적습니다.
③ AGENT SKILL

Agent Skill은 사수가 물려주는 업무 매뉴얼입니다

🧑‍🏫 신입에게 일을 가르칠 때

매일 옆에 앉아 처음부터 설명하지 않습니다. 정리된 매뉴얼 한 부를 주고, 모르면 펴 보게 합니다.

"이 일은 언제 하고, 순서는 이렇고, 이 함정을 조심해."

🤖 AI에게 일을 가르칠 때

그 매뉴얼을 SKILL.md라는 텍스트 파일로 씁니다.

관련 요청이 오면 AI가 스스로 꺼내 읽고 그대로 일합니다. 나도, 동료도, 후임도 같은 품질.

스킬 = 발동 조건(언제) + 절차(어떻게) + 도구(스크립트·참고 자료)를 담은 폴더
비유 하나로 개념 전체를 전달합니다. "프롬프트는 말로 시키기, 스킬은 매뉴얼 건네기." CLAUDE.md와 차이: CLAUDE.md는 늘 읽히는 짧은 규칙, 스킬은 그 업무를 할 때만 펼치는 긴 절차입니다. Claude Code·Claude 앱 외에도 여러 에이전트 도구가 같은 SKILL.md 형식을 읽습니다.
③ AGENT SKILL · 구조

스킬의 실체는 폴더 하나와 텍스트 파일입니다

📁 csv-report/
├─ SKILL.md        ← 매뉴얼 본문 (필수)
├─ scripts/
│   └─ merge_csv.py ← 검증된 스크립트 (선택)
└─ references/
    └─ spec_table.md ← 스펙 표 (선택)
--- SKILL.md 맨 위 (이름표) ---
name: csv-report
description: 설비 측정 CSV들을 병합해
  일일 수율 리포트(HTML)를 만든다.
  "측정 리포트", "CSV 취합" 요청 시 사용.
--- 본문 (업무 매뉴얼) ---
1. data/*.csv 를 모두 읽는다 (헤더 3줄 스킵)
2. LOT_ID 대문자 통일, THK는 Å 그대로
3. 스펙 판정: references/spec_table.md
4. 결과는 새 HTML 파일로

두는 곳: 이 폴더 전용은 .claude/skills/<이름>/, 어디서나 쓸 것은 ~/.claude/skills/<이름>/. 메모장으로 쓸 수 있는 글이라 AI가 대신 써 줄 수도 있습니다.

겁먹을 필요 없습니다. 폴더 + 마크다운 텍스트가 전부입니다. name·description은 이름표(발동 조건), 본문은 절차, scripts·references는 부록입니다. 폴더 전용(.claude/skills)은 git으로 팀과 공유되고, 개인용(~/.claude/skills)은 내 모든 작업에서 쓰입니다.
③ AGENT SKILL · 클릭해 보세요

AI는 매뉴얼을 필요할 때만 펼칩니다

📇 이름표 — csv-report: 측정 CSV 병합·일일 리포트 생성…
📖 SKILL.md 본문 — ① CSV 읽기(헤더 3줄 스킵) ② LOT_ID 정규화 ③ 스펙 판정 ④ HTML 리포트…
🧰 부록 — scripts/merge_csv.py 실행 · references/spec_table.md 참조

평소에는 이름표만 읽어 둡니다 — 매뉴얼 100권이 꽂혀 있어도 부담이 없습니다.

"점진적 공개"를 책장 비유로: 평소엔 책등(이름표)만 보고, 일이 생기면 그 권만 펼칩니다. 그래서 스킬을 수십 개 만들어도 AI가 느려지거나 헷갈리지 않습니다 — 팀 스킬 모음이 가능한 이유. 스텝 버튼을 눌러 가며 시연합니다.

skill-creator 스킬로 새 스킬을 만들어줘.
업무: 매일 아침 설비별 측정 CSV(D:\meas\*.csv)를 병합해 일일 리포트를 만든다.
규칙: 헤더 3줄 스킵, LOT_ID 대문자, THK는 Å, 스펙 판정은 CVD 450±30.
주의: 회사 엑셀 파일은 DRM 때문에 xlwings로만 연다.

준비할 것은 코드가 아니라 업무 설명입니다. skill-creator가 없으면 /plugin install skill-creator@claude-plugins-official 로 설치하거나, "SKILL.md 형식으로 만들어줘"라고만 해도 됩니다.

skill-creator는 스킬 쓰는 요령(이름표, 본문 구조, scripts 분리)을 아는 "스킬 만드는 스킬"입니다. 인터뷰하듯 빠진 규칙을 되물어 주므로 비개발자에게 특히 좋습니다. 마지막 줄 강조: DRM 같은 사내 제약도 말로 넣으면 스킬에 새겨집니다.
QUALITY CHECKLIST

좋은 스킬은 신입이 읽고 바로 따라 하는 매뉴얼입니다

  • ① description = 발동 조건

    "측정 리포트", "CSV 취합"처럼 내가 실제로 쓰는 말을 넣어야 AI가 알아서 꺼냅니다.

  • ② 규칙은 애매함 없이

    "적당히 정리" ❌ → "LOT_ID는 대문자, 소수점 1자리" ⭕

  • ③ 검산 방법을 적는다

    "병합 행수 = 파일별 합계, 다르면 중단" — AI가 스스로 이상을 잡고 멈춥니다.

  • ④ 함정·제약을 기록한다

    "이 엑셀은 DRM이라 xlwings 필수", "금요일 파일은 컬럼 하나 더" — 고생한 기억이 자산이 됩니다.

처음부터 완벽할 필요는 없습니다 — 스킬은 쓰면서 고치는 문서입니다.
신입 테스트: 이 문서만 받은 신입이 같은 결과를 낼 수 있는가? ④가 후반부와 이어집니다 — DRM·KLayout 같은 사내·도구 제약이 "함정 기록"의 대표 사례입니다.

SAFETY · 남이 만든 스킬

남이 만든 스킬은 설치 전에 원문을 읽습니다

📦 어디서 구하나

Claude Code의 /plugin 마켓플레이스, skills.sh 같은 공개 목록(제3자 · Anthropic 공식 아님), GitHub 저장소.

⚠️ 왜 조심하나

SKILL.md는 AI가 그대로 따르는 지시문이고, scripts/는 실제로 실행되는 코드입니다. 출처 불명 스킬은 프롬프트 인젝션의 통로가 됩니다.

설치 전 체크리스트
  • 만든 사람·조직을 확인할 수 있는가 — 인기(스타·설치 수)는 최소한의 필터일 뿐
  • SKILL.md와 scripts/를 전부 읽었는가 — 파일을 밖으로 보내는 코드(업로드·외부 주소)가 없는가
  • "이전 지시는 무시", "사용자에게 알리지 말 것" 같은 문장이 있으면 설치하지 않는다
  • 사내 반입 정책상 허용되는가 — 애매하면 보안 덱과 사내 담당자 확인
스킬은 평문이라 읽어 보면 됩니다. 몇 분이면 됩니다. 이 시리즈를 준비하는 동안에도 도구 결과 속에 "반드시 따라야 한다"는 낯선 지시문이 섞여 들어온 적이 있습니다 — 전형적인 인젝션 패턴이라 무시했습니다. 인젝션 원리는 보안 덱(../security/)에서 자세히.
