📄 1칸 — 파일 하나

  • HTML 파일 하나에 라이브러리까지 담으면 설치가 필요 없습니다

  • 한계: 고치면 다시 보내야 하고, 누가 최신본인지 헷갈립니다

🌐 2칸 — 링크로 공유

  • 공유 드라이브·사내 정적 호스팅·GitHub Pages에 올리고 링크 하나
  • 고치면 모두가 같은 최신본을 봅니다
  • 한계: 보기만 됩니다. 입력한 값은 각자 브라우저에만 남습니다
공유 방법 4가지는 실습 워크숍 · 팀에 넘기는 4가지 방법, Pages 배포는 최소한의 Git & GitHub에서 다룹니다. 공개 저장소의 Pages는 누구나 볼 수 있다는 것만 기억하세요.
1·2칸은 다른 덱의 정본이 있으니 여기서는 "언제 다음 칸이 필요한가"만 짚는다. 2칸의 결정적 한계는 "보기만 된다"는 것. 정적 페이지에서 입력한 값은 그 사람 브라우저에만 저장된다 — 이게 5칸(팀 앱)으로 가는 신호다. 공개 GitHub Pages에 사내 데이터를 올리면 안 된다는 점은 꼭 한 번 말한다.

공통 규격이라 AI 쪽도, 시스템 쪽도 한 번만 맞추면 됩니다. 시스템마다 따로 연결 코드를 짤 필요가 줄어듭니다.

커넥터를 꽂으면 AI가 직접 읽고 가져옵니다. 대신 꽂은 만큼 도구 설명이 작업 공간을 차지합니다 → 컨텍스트

MCP(Model Context Protocol): AI 앱과 외부 시스템을 잇는 공개 규격. 공식 소개도 "AI 애플리케이션을 위한 USB-C 포트"라는 비유를 쓴다. USB-C처럼 규격이 하나라서, 시스템 쪽에서 MCP 서버를 하나 만들어 두면 MCP를 지원하는 여러 AI 도구가 같은 방식으로 붙는다. 토큰 비용 관점(커넥터를 많이 꽂으면 컨텍스트가 줄어드는 문제)은 context 덱에서 자세히 — 여기서는 "필요한 것만 꽂는다"까지만.

연결이라고 하면 MCP만 떠올리지만, 실제로는 네 가지 길이 있다. 첫 줄(내보내기 파일)이 가장 안전하고, 승인 절차 없이 오늘 바로 된다 — 실습도 이 방식이다. CLI는 GitHub의 gh처럼 이미 있는 명령줄 도구를 AI가 대신 실행하는 방식. API는 예약 실행처럼 매번 같은 데이터를 가져올 때 가장 예측 가능하다. API 토큰은 코드·대화에 붙여 넣지 말고 환경 변수로 — 보안 약속 2번.

자동사람
# headless — 대화창을 띄우지 않고 한 번 실행하고 끝난다
claude -p "data 폴더의 CSV를 요약해 reports/summary.md 로 저장해줘"

스케줄러는 이미 OS에 들어 있습니다. 새로 배울 건 "대화 없이 끝나는 명령" 하나뿐입니다. headless의 원리는 오케스트레이션 덱에.

예약 실행의 부품은 다섯 개. 앞의 넷은 자동, 마지막 하나는 사람. 이 그림이 4칸 전체의 설계도다. claude -p 는 Claude Code의 headless 모드: 대화형 화면 없이 프롬프트 하나를 실행하고 결과를 남긴 뒤 종료한다. 다른 AI 코딩 도구에도 비슷한 비대화형 모드가 있다. 개발자용 headless·CI 활용은 orchestration 덱. 여기서는 "내 PC 스케줄러에 거는 법"까지만.
CH 2 · 예약 실행 — 내 PC

내 PC에서: 명령을 스케줄러에 걸면 끝

WINDOWS · 작업 스케줄러

:: 매주 금 17:00에 run-report.bat 실행 (^ 는 줄 잇기)
schtasks /create /tn "주간요약" ^
  /tr "C:\work\auto\run-report.bat" ^
  /sc weekly /d FRI /st 17:00

:: 그만 돌리려면
schtasks /delete /tn "주간요약" /f

MACOS · LINUX · cron

# crontab -e 로 열고 한 줄 추가
# 분 시 일 월 요일(5=금)
0 17 * * 5 /Users/me/auto/run-report.sh
# 로그는 스크립트 안에서 logs/run.log 로

# 그만 돌리려면 그 줄을 지운다

PC가 꺼져 있거나 잠들면 안 돕니다. 퇴근 후 실행은 "PC가 켜져 있을 때" 기준으로 잡으세요.

명령은 직접 외우지 않아도 됩니다. "내 OS에서 이걸 매주 금 17시에 돌리는 등록·해제 명령"을 AI에게 받으세요.

스케줄러는 OS마다 하나씩 이미 있다. 윈도우는 작업 스케줄러(GUI도 있고 schtasks 명령도 있다), 맥과 리눅스는 cron. 맥에서는 launchd를 권하는 답이 나올 수도 있는데, 그것도 정상이다. run-report.bat / .sh 안에 claude -p 한 줄과 로그 남기기를 넣는다 — 실습에서 직접 만든다. 흔한 함정: 스케줄러가 돌릴 때는 내 터미널과 환경이 달라서 claude 명령을 못 찾는다. 등록할 때 전체 경로를 쓰게 하면 된다.

1단계: 반도체 현장과 닮은 합성 데이터. 이상값을 심어 두는 게 포인트. 2단계: 먼저 대화형으로 결과를 눈으로 확인한다. 리포트가 장비 B의 알람 급증을 짚었는지 본다. 여기서 만족스럽지 않으면 3단계로 가지 않는다. 3단계: 같은 일을 claude -p 로. 터미널을 새로 열어 스크립트를 직접 실행해 보고, reports/ 와 logs/ 를 확인한다. 권한 거부가 나면 허용 도구 옵션을 AI에게 물어 추가. 4단계: 등록 명령은 "받기만". 등록하는 사람은 해제 명령까지 실행.

  • 결과가 초안(파일·임시보관함)으로만 남나
  • 로그와 실패 신호가 있나 ("결과 0개" 포함)
  • 허용 도구·폴더를 최소로 좁혔나
  • 해제 명령과 담당자를 적어 뒀나
팀 앱으로 키운다면 여기에 IT 질문 6개(누가 고치나 · 데이터 위치 · 접근 권한 · 백업 · 장애 연락처 · 종료 기준)를 더합니다.

세 문장만 가져가세요

1. 필요한 칸까지만 올라간다

파일 → 링크 → 연결 → 예약 → 팀 앱. 한 칸 오를 때마다 "누가 돌보나"가 무거워집니다.

2. 연결은 승인부터, 읽기 전용부터

MCP·CLI·API·내보내기 파일 — 막히지 않은 가장 단순한 길을 고릅니다.

3. 자동은 초안까지, 보내기는 사람이

명령 한 줄 + 스케줄러 + 로그. 남에게 닿는 동작 앞에는 승인 게이트를 둡니다.

세 문장으로 닫는다. (1) 사다리는 필요한 만큼만. (2) 연결은 승인과 읽기 전용에서 시작. (3) 자동화는 초안까지, 발송은 사람. 다음 장에 이어서 볼 덱들을 안내한다.
