WHY

발표 준비 시간은 꾸미기와 막판 수정에서 샙니다

💡 내용 정리

말할 거리를 고르고 순서를 잡는 일. 진짜 내 일이고, 제일 재미있는 부분.

🎨 장표 꾸미기

정렬 맞추고, 색 고르고, 아이콘 찾고, 폰트 바꾸기. 밤늦게까지 손으로 맞추는 일.

🔁 마감 전 수정

"5장이랑 12장 순서 바꿔줘" 한 마디에 목차·번호·디자인을 다시 손봐야 합니다.

꾸미기와 수정은 AI가 가장 잘하는 종류의 일입니다 — 사람은 내용만 붙들면 됩니다.

"장표 꾸미기에 시간을 얼마나 쓰시나요?" 물어 공감을 끌어냅니다. 오늘의 약속: 꾸미기·수정 시간을 AI에게 넘기는 5단계.
WHY HTML

AI와 일하기엔 HTML 슬라이드가 편합니다

📝 텍스트 = AI의 모국어

PPT 파일은 AI가 직접 읽고 고치기 까다롭지만, HTML은 통째로 읽고 통째로 고칩니다. "전부 다크 테마로" 한 마디면 됩니다.

🌿 git으로 버전 관리

모든 수정이 diff로 남고, 언제든 롤백. 발표자료_최종_진짜최종_v3.pptx와 작별합니다.

🔗 링크 하나로 공유

GitHub Pages에 올리면 주소 하나로 공유됩니다. 발표장 PC에 브라우저만 있으면 됩니다.

✨ 살아있는 슬라이드

코드 하이라이트, 그려지는 차트, 눌러 보는 데모를 슬라이드 안에 넣을 수 있습니다. 이 덱의 로드맵 장처럼.

핵심은 첫 카드 — "AI가 결과물을 직접 만들고 직접 고칠 수 있는 포맷"이라는 점. 나머지 셋은 따라오는 보너스.

디자인을 열 마디 말로 설명하지 말고,
만족했던 실물 하나를 보여주세요.

✗ 말로 설명
세련되고 모던하고 미니멀한 다크 테마로,
전문적이면서 트렌디한 느낌으로 만들어줘
✓ 실물로 설명
reference.html 이랑 같은 수준·같은
스타일로 만들어줘

내가 말한 "모던함"과 AI가 떠올린 "모던함"은 다른 그림입니다. 형용사는 해석할 여지를 남기지만, 파일은 남기지 않습니다.

오늘 하나만 가져간다면 이 장입니다. 예시 하나가 긴 지시문보다 강하다는 원리 — 프롬프트 덱의 "예시로 보여 주기"와 같습니다.
LV.1

앵커링 프롬프트 — 그대로 복사해 씁니다

PROMPT — 레퍼런스 앵커링
reference.html은 내가 가장 만족했던 발표자료야.
새 주제 "◯◯◯"로 발표 슬라이드를 만들어줘. 15장 내외.

- reference.html의 디자인 시스템을 그대로 따를 것
  (배경·색상 팔레트·폰트·카드/코드블록 컴포넌트·등장 애니메이션)
- 슬라이드 구성 문법도 참고할 것 (타이틀 → 훅 → 본론 → 정리 → Q&A)
- 내용만 새로 쓰고, 완성도는 레퍼런스 이상을 목표로

주는 방법 — 대화에 파일 첨부, 또는 작업 폴더에 reference.html을 두고 경로만 알려주기. 에이전트라면 후자가 편합니다.

왜 "이상"인가 — 목표를 레퍼런스 "동일"로 잡으면 축소 복사가 나오기 쉽습니다. 상향 목표가 디테일을 지켜줍니다.

복사 버튼 시연. 요점 3개: ①그대로 따를 것 ②구성 문법도 ③이상을 목표로. 특히 "디자인 시스템"이라는 단어가 색·폰트·컴포넌트를 묶어서 전달해준다.

AFTER reference.html 첨부

프롬프트에 늘어난 것은 단 한 줄 — "reference.html처럼".

비교 목업. 실제 발표에선 진짜 생성 결과 스크린샷으로 교체해도 좋다. 메시지: 노력의 증가분(한 줄) 대비 품질의 증가분이 비대칭적으로 크다.
LV.1

레퍼런스는 마음에 든 덱 하나를 통째로

1️⃣ 마음에 든 덱 "한 개"면 충분합니다

여러 개를 주면 스타일이 섞여 어느 쪽도 아닌 결과가 나옵니다. 제일 만족했던 하나만 고르세요.

2️⃣ 통째로 주세요 — 스타일은 <head>에 삽니다

"예쁜 부분만" 발췌하면 색 토큰과 컴포넌트 정의가 잘려나갑니다. 파일 전체가 곧 명세입니다.

3️⃣ 없으면 이 시리즈를 가져가세요

github.com/geniuskey/vibe-coding — 아무 폴더의 index.html이나 레퍼런스로 쓰셔도 됩니다. "회사 CI 색으로 팔레트만 바꿔줘"라고 덧붙이면 됩니다.

실용 팁 3개. 마지막 카드에서 저장소 주소 공유 — 오늘 당장 써볼 수 있는 출발점을 손에 쥐여준다.
LV.2

피드백은 장 번호 + 증상으로 줍니다

한 번에 완성되지 않으니 2~4바퀴 다듬습니다. 다듬기 루프의 일반 원칙은 AI에게 일 시키는 법에서 — 여기선 슬라이드 요령만.

✗ 형용사 피드백
전체적으로 좀 더 예쁘게, 있어 보이게 해줘
✓ 장 번호 + 증상
3번 장 제목이 두 줄로 넘쳐. 한 줄로 줄이고,
7번 장 카드 3개는 높이를 맞춰줘

📸 말로 안 되면 스크린샷을 붙여넣습니다

깨진 장을 캡처해 "여기 카드가 겹쳐"라고 붙이면, 백 마디 설명보다 정확합니다. 디자인 피드백은 이미지가 가장 빠릅니다.

"예쁘게"는 지시가 아닙니다. 장 번호로 위치를 찍고, 눈에 보이는 증상을 말합니다 — 모니터를 손가락으로 가리키듯. 스크린샷 피드백은 실제로 시연하면 반응이 좋습니다.
LV.2

AI가 스크린샷을 찍어 스스로 고치게 합니다

매번 내가 확인하는 것도 일입니다. 에이전트에게 브라우저로 자기 결과물을 열어 보고 검사하게 시킵니다.

PROMPT
덱을 브라우저로 열어서 장마다 스크린샷을

LV.4

slide-deck 스킬을 복사하면 요청이 한 줄

# slide-deck/SKILL.md (발췌)
name: slide-deck
description: 발표 슬라이드(HTML/reveal.js)를 만든다.
  "슬라이드", "발표자료", "세미나 자료" 요청 시 사용.
## 절차
1. template.html을 새 폴더로 복사해 시작
2. 주제·청중·분량 확인 → 목차부터 합의
3. 내용 채우기 — 본문 6줄 이하, 제목 한 줄
4. 브라우저로 전 장 검사, 문제는 스스로 고침
