# LLM에게 우리의 지식을 가르치는 법

LLM 시대의 지식 정리 세미나 슬라이드 (reveal.js, 단일 `index.html`).
**LLM 위키 → RAG → 지식 그래프 → 온톨로지** — 네 개념을 순서(성숙도)대로 소개하고 결론은 "작게 시작",
후반부는 Claude Code 같은 에이전트에게 **프롬프트로 시키는 실습 5개**로 쓸 만한 파일을 직접 만들어 봅니다.

## 무엇을 다루나

| 챕터 | 내용 | 형식 |
| --- | --- | --- |
| CH 1 · LLM과 지식 | 신입사원 비유, 환각의 정체와 처방, 지식을 넣는 3가지 방법(통째로·RAG·파인튜닝), 오늘의 지도 | 이론 |
| CH 2 · LLM 위키 | 못 읽는 곳의 지식은 없는 지식, Markdown, 작성 4원칙, INDEX.md 진입점(CLAUDE.md는 → `agent-skills/`), 위키의 한계 | 이론 |
| CH 3 · RAG | 검색 증강 생성 3단계, 임베딩·벡터 DB(접힘), 청킹, 키워드 vs 벡터, 실패 모드 4가지, Agentic RAG | 이론 |
| CH 4 · 지식 그래프 | 연결 질문, 트리플·GraphRAG(접힘), multi-hop, "전부 그래프화하지 마라" | 이론 |
| CH 5 · 온톨로지 | 용어 불일치, 구조화의 사다리·부품 5가지(접힘), 용어사전으로 시작하기 | 이론 |
| CH 6 · 작게 시작하기 | 네 도구는 층, "문서 10개 → 신호가 올 때만 한 칸씩" 로드맵 | 이론 |
| 실습 1~5 | 위키+INDEX+답변 규칙 → 출처 달린 FAQ → 담당·관계 지도 → 용어사전+규칙 점검 → 우리 팀 다음 단계 | 실습 |
| 부록 | 프롬프트 치트시트 | — |

전체 모드 37장(핵심 모드 30장), 약 90분 (개념 ~40분 + 실습 ~50분) 구성입니다.
실습 준비물은 **에이전트 도구(Claude Code 등) + 빈 폴더**가 전부입니다 — 임베딩 API나 벡터 DB 설치 없이
개념을 체험하도록 설계되어 있습니다.

### 실습이 남기는 것

| 실습 | 결과물 | 완료 기준 (눈으로 확인) |
| --- | --- | --- |
| 1 · 위키 만들기 (15분) | `wiki/` · `wiki/INDEX.md` · `CLAUDE.md`(3줄) | INDEX.md 한 장으로 전체가 보이고, 낡은 규정에 "폐기됨" 표시 |
| 2 · 근거 있는 답변 (10분) | `FAQ.md` | 없는 내용은 "문서에 없음", "휴가"로 물어도 연차 문서를 찾음, FAQ 답 전부에 출처 |
| 3 · 관계 지도 (10분) | `triples.csv` · `team-map.html` | 지도가 열리고, 장비 교체 영향을 경로로 답함 |
| 4 · 용어 통일 (10분) | `GLOSSARY.md` (+ 규칙 두 줄) | 쪼개졌던 ACME 노드가 합쳐지고 규칙 위반 목록이 나옴 |
| 5 · 우리 팀에 옮기기 (5분) | `NEXT-STEPS.md` | 이번 주 할 일 3줄 + 다음 단계로 넘어갈 신호 |

진짜 팀 문서로 실습할 때는 시리즈 공통 보안 약속을 따른다: ① 회사 기밀·실데이터는 사내 승인 도구에서만 — 애매하면 넣지 않는다.
② API 키·비밀번호는 코드·대화·커밋에 남기지 않는다 — 새어 나갔다면 삭제가 아니라 재발급. ③ 회사 정책이 이 자료보다 우선한다. → `../security/`

## 실행

- **정적 열람**: `index.html`을 브라우저로 열거나 정적 호스팅(GitHub Pages 등)하면 슬라이드만 동작합니다.
- **실제 발표 (실시간 Q&A 포함)**: 저장소 루트에서

  ```bash
  npm run dev
  # 발표자: http://localhost:8080/knowledge/?present
  # 청중:   http://localhost:8080/knowledge/
  ```

  질문·반응은 발표 플랫폼의 단일 세션으로 이어집니다 (루트 README 참고).

| 그래프 추출 | 문서에서 트리플을 추출해줘 — 개체 4종·관계 4종만 허용, 근거 표기 |

| 멀티홉 | X와 Y의 연결 경로를 그래프에서 전부 찾아줘 |
| 용어사전 | 같은 대상을 다르게 부르는 용어를 찾아 GLOSSARY.md 만들어줘 |
| 규칙 | 용어사전 아래에 지켜야 할 규칙 두세 줄을 적어줘 |
| 품질 검사 | 규칙을 어기는 문서를 찾아 목록으로 보여줘 |
